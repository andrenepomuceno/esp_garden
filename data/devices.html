Which peripherals this board has is configuration, not a build flag. A sensor is fitted if and only if its key exists in io; the number of relays is the length of io.relays and the number of probes the length of io.soilMoisture. Adding and deleting here rewrites config.json, which the device only reads at boot — so nothing changes until the device restarts.
Relays
# Name GPIO Active level Now
Index 0 is the watering relay on every board. TalkBack's watering:<ms>, the legacy watering parameter of /control and ThingSpeak field 2 all address it, and every schedule targets a relay by index — so deleting row 0, or deleting any row above another, changes what all of those mean. Active level is the level that energises the relay: 0 for the usual opto-isolated board, which idles high. Test switches the running relay on for three seconds, on the pin the device booted with, not the one selected above.
Soil moisture probes
# Name GPIO Dry (air) Wet (water) Sensor Power Fed by Reading
Each probe carries its own two reference readings: dry taken in air, wet taken submerged. They live in the moisture array, which stays parallel to this table — delete a probe here and its calibration goes with it instead of sliding onto the next probe. While the two are equal the probe counts as uncalibrated and the dashboard shows no Dry/Humid/Wet badge, which is honest rather than a band invented from nothing. A disconnected probe does NOT read at a rail — measured here, an unplugged one sat mid-scale and quiet, indistinguishable from soil by value alone — so it is not a usable dry anchor either.
Sensor is a free label plus the probe's polarity. Reads lower when wet is what the capacitive v2 modules do; a resistive divider usually does the opposite. Getting it backwards inverts the number on the dashboard without the classifier noticing, because the classifier accepts either direction. Two readings settle it: one in air, one in water — whichever is higher tells you the sign. Power names a GPIO that energises the probe only while it is read. A resistive probe left permanently powered is an electrolysis cell in wet soil and dissolves its own electrode in weeks; at a 1 s period and a few milliseconds of reading, it is live under 1 % of the time. Mind the current: an LM393 module with its LED draws around 20 mA, which is most of what one GPIO should source, so two of them want a small MOSFET rather than a shared pin. Changing the label or the polarity DISCARDS that probe's trained model — which is the point, since the stored bands describe a sensor that is no longer in the pot.
Single-instance sensors
Fitted Device Name GPIO Options Reading
Unticking a box removes the key from io entirely, which is how the device is told the hardware is not there. A phantom sensor is not harmless: a flow meter that is not wired counts interference as flow, and a float switch that is not wired reads at its pull-up, which means “empty”. A name is the dashboard label /data.json keys Inputs by; on the DHT it is a prefix, because one pin produces two channels. Names are labels, not identifiers — telemetry keys and the history record stay positional, so a rename never rewrites stored data.
